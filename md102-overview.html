ID・コンプライアンス管理
🏛️
Microsoft Entra ID（旧 Azure AD）
Entra ID ポータル → デバイス → デバイスの設定
ID基盤

エンドポイント管理の中核となるクラウド ID プラットフォーム。デバイス参加方式によって管理手段・Intune 自動登録の挙動が変わるため、Join 方式の選択が最重要。

📋 デバイス参加方式の比較
Azure AD Joinクラウドネイティブ / Intune MDM 自動登録 / 新規 PC 向け
Hybrid Azure AD Joinオンプレ AD + Entra ID 両方 / MECM 共存 / 既存 PC 向け
Azure AD 登録BYOD / 個人デバイス / MAM 管理向け (MDM 任意)
MDM 自動登録Azure AD Join 時 → Intune へ自動登録
— デバイスグループ —
動的グループOS / モデル / 部署 / Join 方式で自動分類
割り当て基準デバイスグループ または ユーザーグループ
💡Azure AD Join = Intune 自動登録 の流れが試験頻出。オンプレ AD が不要な新規環境では AAD Join + Intune がクラウドネイティブの標準構成。

条件付きアクセス（Conditional Access）
Entra ID → 保護 → 条件付きアクセス → 新しいポリシー
アクセス制御

「IF 条件 THEN アクション」の形式でアクセスポリシーを定義する Entra ID の機能。コンプライアンスポリシーと組み合わせることで、非準拠デバイスをリソースから自動遮断できる。

📋 ポリシー構成例（デバイス準拠必須）
— 割り当て —
ユーザーすべてのユーザー（除外: Break Glass アカウント）
クラウドアプリOffice 365 / Microsoft 365 全体
条件: デバイスプラットフォームWindows / iOS / Android
— アクセス制御 —
許可（Grant）✅ 準拠デバイス必須　OR　MFA 必須
セッションサインイン頻度: 1 日
ポリシー状態レポートのみ → テスト後に有効化
💡Break Glass アカウント（緊急管理者）は必ず CA 除外に設定。テナント全体のロックアウトを防ぐために MFA なしの専用アカウントを用意する。

Windows Hello for Business / MFA
Intune → デバイス → 構成プロファイル → Windows Hello for Business
パスワードレス

PIN・顔認証・指紋認証でパスワードなしに Entra ID へ認証する仕組み。認証情報はデバイスの TPM チップに保存されるためフィッシング耐性が高く、ゼロトラストの基盤となる。

📋 Intune 構成プロファイル設定例
Windows Hello for Business有効
PIN 最小長6 桁
PIN 最大長127 桁
生体認証許可
高度ななりすまし防止有効
PIN 回復有効
TPM 要件TPM 2.0 以上
💡WHfB は非対称鍵認証のためパスワードがネットワークを流れない。Pass-the-Hash / Pass-the-Ticket 攻撃を無効化できる点が試験で問われる。

登録ステータスページ（ESP）
Intune → デバイス → 登録 → 登録ステータスページ
展開制御

Autopilot 展開中、すべてのポリシー・アプリ・証明書が適用完了するまでデスクトップへの進行をブロックする機能。「設定未完了な状態でのログイン」を防ぐ。

📋 ESP プロファイル設定例
アプリとプロファイルの追跡はい
エラー表示はい
ユーザーによるログ収集許可
タイムアウト（分）60
タイムアウト時メッセージIT ヘルプデスクへご連絡ください
ブロックするデバイスアプリDefender for Endpoint / VPN クライアント
— 2 フェーズ構成 —
デバイスフェーズデバイスポリシー・証明書の適用（ログイン前）
ユーザーフェーズユーザー向けアプリ・設定の適用（ログイン後）
💡ESP の「ブロックするアプリ」に必須アプリを入れすぎると展開時間が長くなる。セキュリティ上重要なアプリ（Defender・VPN）のみ指定するのが実運用のベストプラクティス。
🖥️
Microsoft Deployment Toolkit（MDT）
MDT Deployment Share → タスクシーケンス → WDS 連携
オンプレ展開

オンプレミスで Windows イメージをネットワーク越しに大規模展開するツール。WDS と組み合わせ PXE ブートで起動し、タスクシーケンスで OS 展開からアプリ・ドメイン参加まで完全自動化できる。

📋 標準タスクシーケンス構成例
1. 初期化BIOS / UEFI チェック、ディスクパーティション作成
2. OS イメージ適用WIM / ESD イメージを展開
3. Windows 設定プロダクトキー / タイムゾーン / ロケール
4. ドライバ適用モデル別ドライバパック注入
5. Windows 更新WU 経由で最新パッチ適用
6. アプリインストール必須アプリの自動インストール
7. ドメイン参加オンプレ AD へ参加
— 展開方式 —
LTI（Lite Touch）最小限の対話で MDT のみで自動展開
ZTI（Zero Touch）MECM と連携して完全無人展開
💡クラウド移行済み環境では MDT → Autopilot 移行が推奨。ただし試験では MDT・WDS・タスクシーケンスの基礎知識も問われる。

デバイス管理・維持
☁️
Microsoft Intune（MDM / MAM）
intune.microsoft.com — Microsoft Intune 管理センター
クラウド MDM

MD102 試験の中心となるクラウドエンドポイント管理サービス。MDM（デバイス全体管理）と MAM（アプリ単位管理）の両方を提供し、Windows / iOS / Android / macOS を一元管理できる。

📋 デバイス登録方式（Windows）
Autopilotゼロタッチ / 新規 PC 向け（推奨）
Entra ID Join → 自動登録設定アプリ → 会社や学校にアクセス
会社ポータルアプリユーザー自己登録 / BYOD 向け
一括登録（PPKG）Windows 構成デザイナーでパッケージ作成
共同管理（MECM 連携）既存 MECM 環境からの段階移行
— ポリシー適用の優先順位 —
競合時の動作最も制限が厳しい設定が適用される
スコープタグ地域 / 部署ごとに管理者権限を分離
💡登録なしの MAM（MAM-WE）でも組織データを保護できる。BYOD 端末はデバイス全体の MDM 登録を強制せずアプリ保護ポリシーのみ適用が現実的。

共同管理（Co-management）
MECM → クラウドアタッチ → 共同管理の有効化
ハイブリッド管理

MECM と Intune を同時に使い、ワークロード（管理責任）を段階的に Intune へ移行できる橋渡し機能。オンプレ資産を壊さずにクラウド管理へ移行するための重要な過渡的手段。

📋 ワークロード段階移行例
— フェーズ 1：即時移行推奨 —
コンプライアンスポリシーMECM → Intune（CA との連携が必要）
Windows UpdateMECM → Intune（WUfB）
— フェーズ 2：段階移行 —
デバイス構成MECM → Intune（GPO 移行と並行）
エンドポイント保護MECM → Intune（Defender 統合）
— フェーズ 3：慎重に移行 —
クライアントアプリMECM 維持 → 徐々に Intune Win32 へ
— 前提条件 —
要件MECM CB + Hybrid AAD Join + クラウド管理 GW
パイロット機能一部グループのみ先行 Intune 化してテスト可
💡パイロットグループ機能で一部デバイスだけ先に Intune ワークロードへ移行してテストできる。全体展開前の検証に必ず活用する。

デバイス構成プロファイル
Intune → デバイス → 構成プロファイル → プロファイルの作成
OS 設定管理

Intune でデバイスの OS 設定を集中管理するポリシーセット。オンプレのグループポリシー（GPO）をクラウドで代替する重要機能。設定カテゴリは 100 種類以上に及ぶ。

📋 主要プロファイルの種類と用途
ADMX テンプレートEdge / Office / Chrome の GPO をクラウド管理
セキュリティベースラインMS 推奨セキュリティ設定を一括適用
Wi-Fi プロファイルSSID / WPA2-Enterprise / EAP-TLS（証明書認証）
VPN プロファイルAlways-on VPN / Microsoft Tunnel
証明書プロファイルSCEP / PKCS 証明書の自動配布
エディションアップグレードWindows Pro → Enterprise 変換
キオスクモードシングルアプリ / マルチアプリ キオスク
PowerShell スクリプトカスタム設定の一括展開
カスタム OMA-URICSP で提供されていない設定を手動指定
💡GPO 移行には Group Policy Analytics（Intune）が使えるが対応率は 70〜80% 程度。残りは ADMX テンプレートやカスタム OMA-URI で代替する。

Endpoint Analytics
Intune → レポート → Endpoint Analytics
稼働分析

デバイスのパフォーマンス・稼働品質を数値化してスコアリングするサービス。問題デバイスを早期発見し、プロアクティブ修復スクリプトで自動解決まで実施できる。

📋 スコアと測定項目
スタートアップパフォーマンス起動時間・ログイン時間をスコア化（0〜100）
推奨設定スコアセキュリティ / ハードウェア要件の準拠率
アプリの信頼性アプリクラッシュ・ハング頻度
— プロアクティブ修復 —
検出スクリプトExitCode 1 = 問題あり → 修復スクリプト実行
修復スクリプト問題を検出したデバイスのみ自動実行
— 前提条件 —
対象デバイスIntune 登録済み または MECM 共同管理対象
ライセンスMicrosoft 365 E3 / E5 / Intune Plan 1
💡プロアクティブ修復は検出（ExitCode 1 = 問題あり）と修復の 2 本構成。問題を検出したデバイスのみ修復スクリプトが実行されるため効率的。
デバイス保護・更新管理
🔄
Windows Update for Business（WUfB）
Intune → デバイス → Windows 更新 → 更新リング
更新管理

品質更新（セキュリティパッチ）と機能更新（メジャーバージョン）の適用タイミングをグループ（更新リング）ごとにコントロールする。段階的ロールアウトで影響を最小化する。

📋 更新リング構成例（4 段階）
リング 1: Pilot（IT 部門 約 10 台）
品質更新遅延0 日（即時）
機能更新遅延0 日
リング 2: Early Adopters
品質更新遅延7 日
機能更新遅延30 日
リング 3: Broad（一般ユーザー）
品質更新遅延14 日
機能更新遅延60 日
— 共通設定 —
更新デッドライン品質: 3 日　/ 機能: 5 日
再起動アクティブ時間8:00〜18:00（この間は再起動しない）
最大遅延日数品質: 30 日　/ 機能: 365 日
💡品質更新はセキュリティパッチが含まれるため過度な遅延は危険。Pilot → Broad の段階展開で問題を早期発見し、Broad リングへの被害拡大を防ぐ設計が重要。

エンタープライズ向け EDR プラットフォーム。Intune とネイティブ統合されオンボーディングを自動化できる。デバイスリスクスコアをコンプライアンスポリシーに連携しリスクベース CA を実現する。

📋 Intune 統合・設定例
— オンボーディング手順 —
① MDE コネクタIntune → エンドポイントセキュリティ → MDE 接続を有効化
② 構成プロファイルMDE オンボーディングプロファイルをデバイスに展開
— セキュリティ設定 —
クラウド提供の保護有効
リアルタイム保護有効
タンパープロテクション有効（無効化を防ぐ）
ASR ルールOffice マクロブロック / 子プロセス作成禁止
— Intune 連携 —
デバイスリスクスコア低 / 中 / 高 → コンプライアンスポリシーと連携
リスク高デバイス→ 非準拠 → CA でブロック（自動連鎖）
💡ASR（Attack Surface Reduction）ルールはまず監査モードで影響を確認してから強制モードに切り替えるのがベストプラクティス。いきなり強制すると業務アプリがブロックされる場合がある。

BYOD・MAM

MDM 未登録の BYOD デバイスでも組織データを保護できる MAM 機能。個人デバイスのアプリ内の組織データの漏洩を防ぎ、デバイス全体ワイプなしに組織データのみを選択的ワイプできる。

📋 iOS / Android MAM ポリシー設定例
— データ保護 —
組織データのバックアップブロック（個人クラウドへの転送禁止）
他アプリへのデータ送信ポリシー管理アプリのみ
コピー & ペーストポリシー管理アプリ内のみ許可
画面キャプチャ（Android）ブロック
— アクセス要件 —
PIN必須（6 桁以上 / 生体認証でオーバーライド可）
非アクティブ後再認証30 分
— 条件付き起動 —
OS 最小バージョンiOS 16.0 / Android 11.0（古い場合ブロック）
脱獄 / Root 検知アクセスのブロック
— セレクティブワイプ —
ワイプ対象組織データのみ削除（個人データは保持）
💡MAM はデバイス登録不要。「登録なしの MAM（MAM-WE）」が BYOD 対応の核心。デバイス全体を管理せずアプリ内データのみ制御できる。

OneDrive for Business（KFM）
Intune → デバイス → 構成プロファイル → ADMX テンプレート → OneDrive
データ保護

Known Folder Move（KFM）でデスクトップ・ドキュメント・ピクチャを OneDrive に自動バックアップする機能。PC 紛失・交換時のデータ復元を自動化し、ユーザーへの負担をゼロにできる。

📋 Intune ADMX テンプレート（OneDrive）設定例
— 必須設定 —
テナント IDxxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx
— KFM 設定 —
サイレントフォルダ移行有効（ユーザー操作なしで自動移行）
対象フォルダデスクトップ / ドキュメント / ピクチャ
ユーザーによる停止禁止
移行通知表示する
— 同期設定 —
ファイルオンデマンド有効（ローカルストレージ節約）
自動サインイン有効（Entra ID 資格情報で自動ログイン）
帯域幅制限アップロード: 1 Mbps（業務影響防止）
💡KFM 有効化後はデスクトップのファイルも自動的にクラウドバックアップ。新 PC に乗り換えた際、OneDrive サインイン後に即座にファイルが復元されるためユーザーの移行ストレスがゼロになる。
